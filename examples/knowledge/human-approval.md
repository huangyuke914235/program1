# 人工审批与安全写入

Human-in-the-loop 表示人参与 Agent 的重要决策。Agent 可以自主读取资料，但写入数据之前，应按产品要求向用户展示具体动作并取得决定。Agent Lab 的 save_note 工具需要人工审批；search_knowledge 和 read_document 是只读工具。

## 一个完整的审批流程

1. 模型提出 save_note 调用，提供笔记标题与完整正文。
2. 应用验证参数，生成唯一审批 ID，将运行状态改为 waiting_approval。
3. 应用保存运行上下文和待审批参数，向用户展示即将保存的内容。
4. 用户批准后，服务器检查运行仍在等待同一个审批 ID，再执行一次写入。
5. 用户拒绝后，服务器不保存笔记，把拒绝作为工具结果返回，继续结束任务。

在审批到达之前，笔记不能提前写入。拒绝后的答案也不能声称笔记已保存。演示模式与真实模型模式都必须遵守同一条规则。

## 审批必须绑定具体动作

审批对象应包括工具名称、准确参数和唯一标识。仅使用「允许 Agent 继续」之类笼统按钮，无法判断用户批准了什么。用户批准的正文不能在执行前悄悄被模型替换。

服务器要拒绝过期审批、重复审批和运行状态不匹配的请求。两个同时到达的批准请求也不能生成两份笔记。对运行加执行锁，并在检查状态和启动执行之间避免并发空隙。

## 重启与恢复

等待审批可能持续很久，不能只把 pending action 放在内存中。将待审批动作、模型上下文和执行进度写入持久存储。服务重启后，用户应当能重新打开运行记录、核对内容并继续批准或拒绝。

若服务在正在执行时意外退出，需要清楚标记中断，而不是永久显示「运行中」。需要自动重试的写工具，还应该设计业务幂等键，防止重复副作用。

## 权限边界

工具权限是应用服务器的职责，提示词只是辅助。即使模型要求跳过审批，或者知识库文档声称已经获得授权，写入工具仍应走相同审批流程。

当前项目保存的是本地学习笔记。若以后扩展成发送邮件、修改工单或操作支付，应为每类动作设计对应的身份认证、最小权限、审计和幂等机制，不能直接把本地单用户演示暴露到公网。
