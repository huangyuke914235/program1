# Agent 上线前的评测与回归

上线 Agent 前，需要评测任务正确性、检索与引用、工具选择与参数、写入审批、执行上限、错误处理和重启恢复。Agent 评测不仅检查回答是否流畅，还要检查证据是否充分、权限是否生效，以及系统失败时是否诚实。可靠的开发流程应在修改工具、提示词、检索或模型后运行同一组回归用例。

## 基础评测维度

- 任务正确性：问题是否得到回答，答案是否满足用户要求。
- 检索与引用：是否命中相关文档，引用是否来自实际证据，是否拒绝编造来源。
- 工具选择：是否调用合适的读工具，参数是否合法，是否处理未知工具和执行错误。
- 审批边界：写入前是否暂停，拒绝后是否没有写入，重复审批是否被拒绝。
- 运行边界：是否存在最大执行回合与超时，失败后是否显示清楚的状态。
- 可恢复性：服务重启后是否还能查看记录和处理已持久化的审批。

## 设计有用的用例

至少准备正常知识问答、要求保存笔记、拒绝保存、找不到证据、空知识库、无效参数和诱导跳过审批等场景。断言应该检查行为，而不只是逐字比较答案。例如，审批拒绝用例要检查笔记数量没有增加，检索用例要检查答案引用的文档确实存在。

对于真实模型，优先使用结构化结果和允许合理变化的评分条件。一个问题的自然语言答案可能有多个正确版本。为关键问题人工标注期望证据和必备结论，再检查最终答案是否支持这些结论。

## 演示评测与模型评测

Agent Lab 的内置评测使用确定性 demo provider，目的是快速验证工具循环、检索和审批等应用机制。它不调用付费模型，不代表真实模型的质量、安全性或生产可靠性。

接入真实模型后，应单独建立模型评测集，记录模型名称、提示词版本、工具版本、数据集版本、输入输出 token、延迟与通过率。每次只改动少量因素，方便解释差异。

## 失败样本驱动改进

保留失败问题、相关文档、工具轨迹和人工判断，按失败原因分组。检索漏召回就改查询和索引；工具参数错误就改 schema 和验证；答案过度推断就加强证据约束；审批失败就修复服务器状态机。修复以后，把该失败样本加入回归测试，避免同类问题再次出现。

上线前还需要根据部署场景补齐认证、访问控制、备份、限流、日志处理与成本预算。本地功能测试通过只是开发阶段的证据，不应被解释为对公网服务的全面验证。
