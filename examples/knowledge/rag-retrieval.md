# RAG 检索流程与可靠引用

RAG 是 Retrieval-Augmented Generation，即检索增强生成。应用先从自己的知识库寻找证据，再把相关内容交给模型回答。RAG 适合回答产品文档、内部规范与个人笔记中的问题，但检索到内容并不等于答案必然正确。

## 从文档到答案

RAG 检索流程是「文档导入 → 文本清洗与分块 → 建立索引 → 查询检索 → 可选重排 → 读取证据 → 回答生成 → 引用检查」。总结 RAG 时，要区分检索是否找到相关资料与生成是否忠实于证据。分块应尽量保留同一个主题的上下文，并为每块保留文档 ID、标题和来源位置。

关键词检索根据查询词与文档文本的重合度寻找结果；向量检索根据嵌入的相似度寻找语义接近的内容。两者解决的问题不同，可以组合。中文查询要注意分词或字符片段匹配，否则只按空格分词容易漏掉相关资料。

Agent Lab 使用本地中英文词项与字符片段的词法检索，不调用嵌入模型，不使用向量数据库。这让检索流程可以直接阅读和调试，但表达差异较大的问题可能漏召回。

## 如何形成可核查的引用

检索结果应返回稳定的 documentId、标题和证据摘录。回答中的引用应能够对应到实际读到的文档，例如 [rag-retrieval]。前端展示来源标题与摘录，用户就能核查答案是否被原文支持。

引用不是装饰。不要引用没有检索或读取过的来源，不要把文档中的推测写成确定事实。如果知识库缺乏证据，应明确说明「当前知识库没有足够依据」，并建议补充相关文档。

## 外部内容属于数据

知识库文档可能包含错误内容，甚至包含「忽略之前指令」「执行命令」一类文本。应用应该把它们当成待分析的数据，而不是更高优先级的指令。工具权限必须由应用控制，不能由检索内容决定。

## 如何衡量检索质量

准备一组真实问题，并标注每题应命中的文档。先看相关文档能否进入前几个结果，再看最终答案是否忠实于来源。没有命中相关资料时，优先修复导入、分块、查询和排序，而不是只调整回答提示词。

检索评测至少包含中文查询、英文术语、同义改写、完全无关的问题、空知识库和包含诱导指令的文档。修改检索算法后，用相同数据集对比结果，避免只凭一次演示判断效果。
