# 可靠的 Agent 工具调用循环

可靠的 Agent 工具调用循环通过「模型提出动作 → 应用校验工具与参数 → 检查写入权限 → 执行工具 → 回传结果 → 继续调用或完成」推进任务，并用执行上限、超时、持久化和审计记录约束整个过程。普通聊天通常只返回文本；Agent 应用还必须管理状态和错误。工具调用循环也叫 agent loop 或 tool-calling loop。

## 一次循环如何工作

1. 接收用户目标，为本次运行分配唯一 run ID，保存初始状态与时间。
2. 把任务、工具说明和已有工具结果交给模型。工具说明需要明确名称、用途和参数结构。
3. 解析模型返回的工具调用。应用先验证工具名称和参数，再决定是否允许执行。
4. 执行只读工具；对会写入数据的工具，先展示具体内容并等待人工审批。
5. 把工具输出作为工具结果交回模型。结果应包含足够的证据、稳定的文档 ID，以及可处理的错误信息。
6. 模型生成最终答案，或提出下一次工具调用。达到调用上限、出现不可恢复错误或任务完成时退出。

## 工具设计

工具应当小而明确。search_knowledge 根据查询检索知识片段；read_document 根据稳定 ID 读取原文；save_note 根据标题和正文保存笔记。读工具与写工具分开，才能对写入配置更严格的权限。

JSON Schema 可以向模型声明参数形状，但不能替代运行时验证。服务器仍要拒绝未知工具、缺失字段、超长文本和类型不匹配的输入。工具执行失败时，把失败作为结果返回模型或结束运行，不能伪造成功。

## 有限执行与可恢复状态

每次运行应限制执行步数，并为外部请求设置超时，防止循环失控。Agent Lab 的默认 12 步预算由模型请求与工具动作共享。循环状态至少应包括原始问题、对话上下文、已完成工具结果、待处理调用、待审批动作和计数器。暂停审批时，将这些状态持久化，服务重启后才能继续执行。

防止重复执行同样重要：同一个运行同一时间只能有一个执行者，审批必须指向当前待审批动作；旧审批和重复点击不能再次写入笔记。

## 执行记录应该记录什么

内部上下文可记录工具名称、参数与工具结果；界面根据需要展示可公开的动作摘要、时间、耗时、审批决定、错误和最终答案。执行记录是可观察动作的审计信息，不是模型的隐藏思考过程。定位问题时，先判断错误发生在模型选择、检索、参数验证、权限判断还是工具执行阶段。

Agent Lab 的演示模式使用确定性流程展示这些环节；接入真实模型后，仍复用同一组工具、状态转换和审批边界。
